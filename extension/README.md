# Obelisk Bridge

Chrome-розширення для рушія завантаження "Obelisk Bridge" в Obelisk. Не
публікується в Chrome Web Store — встановлюється вручну.

## Встановлення

1. Відкрийте `chrome://extensions`
2. Увімкніть "Режим розробника" (перемикач угорі праворуч)
3. "Завантажити розпаковане" → оберіть цю папку (`extension/`)
4. Клікніть на іконку розширення → введіть адресу вашого Obelisk, логін і
   пароль (ті самі, що на сайті) → "Увійти"

Після входу розширення саме опитує сервер кожні кілька секунд і реагує,
коли з'являється завдання. Ніяких додаткових налаштувань на сайті вмикати
не треба — щойно розширення залогінене й опитує сервер, звичайні
YouTube-завантаження ("відео + звук", без таймкодів) самі почнуть
пробувати пройти через нього, з непомітним відкатом на стандартний yt-dlp,
якщо воно не встигло відповісти.

## Як це працює

Коротко: розширення не завантажує відео саме. Воно перехоплює справжній
PO-токен, який генерує власний JS YouTube під час звичайного відтворення,
і передає лише цей короткий рядок на сервер — сервер підставляє його в
уже готовий SABR-рушій (`app/youtube_sabr.py`) і завантажує відео сам.

Два способи отримати цей токен:

1. **Кнопка "Obelisk" на сторінці відео/Shorts** (поруч з логотипом
   YouTube) — рекомендований спосіб. Клік бере URL і токен, які вже
   назбирались, поки ви дивитесь відео у звичайній (видимій) вкладці, й
   одразу відкриває Obelisk у новій вкладці з підставленим посиланням —
   лишається обрати якість/режим і натиснути "Завантажити". Найнадійніший
   варіант: токен завжди береться зі справжньої, активно відкритої
   вкладки.
2. **Автоматичний фоновий режим** (резервний) — якщо просто вставити
   посилання на сайті Obelisk без кнопки, сервер сам чекає на розширення:
   воно опитує чергу, відкриває приховану вкладку з відео й намагається
   зловити токен там. Менш надійно (YouTube не завжди починає
   відтворення в прихованій вкладці), але спрацьовує без жодної дії на
   самому YouTube.

`capture.js` (перехоплення мережевих запитів сторінки) — найменш
перевірена частина всього цього: немає готової реалізації, на яку можна
було б спертись, тож точний спосіб перехоплення токена, ймовірно,
доведеться уточнювати й підлаштовувати за результатами реальних тестів.
