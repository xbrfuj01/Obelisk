# Obelisk

Набір веб-інструментів, що самостійно хоститься через Docker Compose. Перший інструмент — завантаження відео з YouTube, Instagram, VK, TikTok та інших сайтів, підтримуваних [yt-dlp](https://github.com/yt-dlp/yt-dlp) (конвертер відео — заплановано). Розрахований і на локальну мережу, і на роботу у відкритому інтернеті (див. розділ "Захист доступу" нижче).

## Можливості

- Сторінка-хаб після входу — вибір потрібного інструменту.
- Завантаження відео: вставити посилання, вибрати тип завантаження (відео+аудіо / лише відео / лише аудіо), якість (підтягується автоматично з реального відео, включно з 4K/8K), формат файлу, субтитри.
- Прогрес завантаження в реальному часі, стрічка останніх завантажень.
- Вхід на сайт (логін+пароль, окремо від адмінки) — сесія "запам'ятовується" на пристрої, блокування після кількох невдалих спроб.
- Адмін-панель під логіном/паролем: статистика, історія завантажень, керування файлами (видалення), налаштування (час автовидалення файлів, зміна логінів/паролів, керування входом на сайт).
- Автоматичне видалення застарілих файлів через N годин (за замовчуванням 24).
- Захист від SSRF (заборона посилань на приватні/локальні адреси) та обмеження частоти запитів на завантаження.

## Як це працює

Образ автоматично збирається GitHub Actions ([.github/workflows/docker-publish.yml](.github/workflows/docker-publish.yml)) при кожному push у `main` і публікується в GitHub Container Registry: `ghcr.io/xbrfuj01/obelisk:latest`. `docker-compose.yml` посилається саме на цей готовий образ (`image:`, без `build:`) — тому на сервері **не потрібен ні git, ні вихідний код**, лише сам `docker-compose.yml`.

## Запуск (TrueNAS / Dockge)

1. У Dockge створіть новий стек (Compose) і вставте туди вміст [docker-compose.yml](docker-compose.yml) з цього репозиторію.

2. Одноразово: зробіть пакет `obelisk` у GHCR публічним, щоб Dockge міг стягнути образ без логіну — на GitHub відкрийте свій профіль → вкладка **Packages** → `obelisk` → **Package settings** → **Change visibility** → **Public**. (Якщо лишити приватним — доведеться один раз виконати `docker login ghcr.io` на TrueNAS з Personal Access Token, що має право `read:packages`.)

3. У змінних середовища стека (вкладка Dockge "Environment variables" або прямо в тексті compose) задайте:
   ```
   ADMIN_USERNAME=admin
   ADMIN_PASSWORD=ваш_надійний_пароль
   SECRET_KEY=будь-який_довгий_випадковий_рядок
   SITE_USERNAME=user
   SITE_PASSWORD=ваш_надійний_пароль_для_входу
   ```
   (`SITE_PASSWORD` можна лишити порожнім, якщо сервіс лишається тільки в локальній мережі)

4. Натисніть **Deploy**.

5. Відкрийте `http://<IP-сервера>:30301` — якщо задали `SITE_PASSWORD`, спершу зустріне сторінка входу, а після неї — хаб із вибором інструменту. Адмінка: `http://<IP-сервера>:30301/admin` (логін/пароль — ті, що задали, за замовчуванням `admin`/`admin`; **обов'язково змініть одразу** в розділі "Налаштування").

### Оновлення

Коли в коді з'являються зміни (я їх пушу в `main`) — GitHub сам збирає новий образ за кілька хвилин. На сервері просто натисніть у Dockge **Pull** (стягнути новий образ), потім **Update/Restart** — без git і без ручних команд.

## Змінні середовища

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | Початковий логін адміна (використовується лише при першому запуску, далі зберігається в БД) |
| `ADMIN_PASSWORD` | `admin` | Початковий пароль адміна (аналогічно, далі зберігається як хеш у БД) |
| `SECRET_KEY` | — | Секрет для підпису сесійних cookie адмінки |
| `MAX_CONCURRENT_DOWNLOADS` | `2` | Кількість одночасних завантажень |
| `CLEANUP_HOURS` | `24` | Через скільки годин видаляти завантажені файли (можна змінити в адмінці) |
| `CLEANUP_INTERVAL_MINUTES` | `30` | Як часто перевіряти застарілі файли |
| `PROXY_URL` | — (вимкнено) | Проксі (напр. `socks5://user:pass@host:1080`) для доменів зі списку `PROXY_DOMAINS`. Порожнє значення — проксі не використовується. |
| `PROXY_DOMAINS` | `vk.com,vk.ru,vkvideo.ru,ok.ru,rutube.ru,mail.ru` | Домени, які йдуть через `PROXY_URL` (решта сайтів — напряму) |
| `SITE_USERNAME` | `user` | Логін для входу на сайт (не плутати з адмінкою) |
| `SITE_PASSWORD` | — (вимкнено) | Пароль для входу на сайт. Порожнє — сайт відкритий для всіх, хто його бачить. Логін/пароль можна задати/змінити пізніше прямо в адмінці. |
| `SESSION_MAX_AGE_DAYS` | `30` | Скільки днів "запам'ятовується" вхід (і на сайт, і в адмінку) на пристрої |

## Захист доступу (готовність до відкритого інтернету)

За замовчуванням сайт відкритий для будь-кого, хто до нього достукається — це нормально, поки він доступний лише у вашій LAN. **Якщо плануєте відкрити сайт у публічний доступ (в інтернет)** — обов'язково задайте `SITE_PASSWORD`, інакше будь-хто зможе завантажувати відео вашим сервером і забивати диск.

Що вже вбудовано для роботи у відкритому інтернеті:

- **Вхід на сайт** (логін+пароль) — задається `SITE_USERNAME`/`SITE_PASSWORD`, після перезапуску на сайті з'являється сторінка входу.
- **Довга сесія** — вхід "запам'ятовується" на пристрої на `SESSION_MAX_AGE_DAYS` днів (за замовчуванням 30) через підписану cookie, не треба вводити пароль щоразу.
- **Блокування брутфорсу** — після 5 невдалих спроб (вхід на сайт і в адмінку рахуються окремо) IP-адреса блокується на 15 хвилин.
- **Захист від SSRF** — сервіс відмовляється завантажувати посилання, які вказують на приватні/локальні IP-адреси (10.x, 192.168.x, 127.0.0.1 тощо), щоб форму не можна було використати для сканування вашої домашньої мережі зсередини.
- **Обмеження частоти завантажень** — не більше 20 нових завантажень за 10 хвилин з однієї IP-адреси, щоб не забивали диск флудом запитів.
- Логін/пароль сайту можна задати/змінити/вимкнути пізніше без редеплою — прямо в адмінці, розділ "Налаштування".

Навіть з усім цим **обов'язково додайте HTTPS** перед виходом в інтернет (reverse proxy на кшталт Caddy/Traefik/nginx з TLS, або тунель на кшталт вашого Pangolin, якщо він сам термінує TLS) — без цього пароль і сесійні cookie йдуть мережею у відкритому вигляді.

## Обхід блокування окремих сайтів (VK, RuTube тощо)

Якщо якісь сайти недоступні напряму з вашої мережі (наприклад, заблоковані на рівні країни), можна прогнати запити лише до цих доменів через проксі-сервер, лишивши решту завантажень (YouTube, Instagram, TikTok) без змін.

1. На зовнішньому сервері (VPS), доступному з інтернету, підніміть легкий SOCKS5-проксі, наприклад [microsocks](https://github.com/rofl0r/microsocks) (один бінарник, без залежностей):

   ```bash
   git clone https://github.com/rofl0r/microsocks.git
   cd microsocks && make
   ./microsocks -1 -u myuser -P mypassword -p 1080 &
   ```

   `-1` вмикає обов'язкову автентифікацію (`-u`/`-P`) — проксі дивиться в інтернет, тож без пароля ним зможе скористатись будь-хто, хто знає IP. Відкрийте порт `1080` у фаєрволі VPS лише для потрібних цілей (або обмежте його IP вашого домашнього сервера/тунелю Pangolin, якщо це можливо).

2. У `.env` (або змінних середовища стека в Dockge) додайте:

   ```
   PROXY_URL=socks5://myuser:mypassword@<IP-або-хост-VPS>:1080
   ```

   `PROXY_DOMAINS` за замовчуванням уже містить основні російські відеосервіси — можна лишити як є або відредагувати список.

3. Перезапустіть стек. Тепер запити саме до цих доменів підуть через VPS, а самі файли, як і раніше, зберігаються на вашому домашньому сервері — через проксі йде лише мережевий трафік завантаження, не сховище.

## Дані

- `/mnt/vault/obelisk/downloads` — завантажені файли (том, монтується в контейнер як `/downloads`).
- `/mnt/vault/obelisk/data` — SQLite база з історією та налаштуваннями (том, монтується як `/data`).

## Важливо

- Перш ніж відкривати сервіс в інтернет — задайте `SITE_PASSWORD` і додайте HTTPS (див. розділ вище).
- Логін/пароль `admin`/`admin` за замовчуванням — змініть їх одразу в адмінці після першого запуску.
- Для завантаження контенту дотримуйтесь умов використання відповідних сайтів та авторських прав.
